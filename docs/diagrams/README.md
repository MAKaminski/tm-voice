# Diagrams

## `tm-voice-architecture.html`

A self-contained interactive map of the whole system: the outbound dial path, the two
inbound webhook edges, and the Discord capture pipeline. Open it in a browser — no server,
no network, no build step. It has pan/zoom, light/dark, export, and three guided views
(the dial path, what happens after a call, Discord capture).

`tm-voice.architecture.json` is the source; the HTML is generated from it and should never
be hand-edited.

### Why it is worth trusting

It is generated by [Archify](https://github.com/tt-a1i/archify), which validates the
specification before it will render:

- Every node carrying a `sources` entry is checked against a real path in this repository
  at the pinned revision. A wrong path fails the render rather than shipping a diagram
  that points at a file that does not exist.
- Layout is checked, not eyeballed: edges crossing unrelated nodes, labels masking routes,
  connections following a boundary border, and text that would render below 6px on a
  1440px desktop are all hard errors.

The spec pins `meta.repository.revision`. That is what the `SRC` badges link to, so a
diagram checked in today keeps pointing at the code it was true for.

### Regenerating

The Archify skill is not a dependency of this repo — install it where you work:

```bash
npx skills add tt-a1i/archify -g
```

Then, from a checkout of the skill:

```bash
node bin/archify.mjs validate architecture <path>/tm-voice.architecture.json \
  --quality showcase --repo-root <path-to-tm-voice> --json

node bin/archify.mjs deliver architecture <path>/tm-voice.architecture.json \
  <path>/tm-voice-architecture.html --quality showcase --repo-root <path-to-tm-voice> --json
```

`deliver` is the acceptance step; a non-zero exit is never a pass. Browser evidence is a
separate command and proves something narrower — containment and readability at four
desktop sizes, not that the diagram is pretty or correct:

```bash
node bin/archify.mjs visual-check <path>/tm-voice-architecture.html --json
```

**When the architecture changes, edit the JSON and bump `meta.repository.revision` to the
commit the diagram is true for.** A stale revision is worse than no revision, because the
`SRC` links keep working while pointing at the wrong code.

### Two things it deliberately does not draw

Both are stated on the cards instead, because drawing them cost more in legibility than
they added in truth:

- The API's own Postgres access. The worker edge carries "state lives in Postgres"; both
  services use the same Drizzle schema.
- The capture service's R2 upload. Capture writes speaker tracks to R2 as well as rows to
  Postgres.
